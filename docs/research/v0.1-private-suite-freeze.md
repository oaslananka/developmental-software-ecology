# V0.1 Private Functional Suite Freeze — M21

M21 freezes the first private held-out suite bound to the public M20
DSE Utility Kernel opportunity.

The suite bytes, concrete inputs, expected outputs, case composition and
case-level diagnostics are intentionally absent from this repository.

```text

suite_id                 = v0_1-hidden-functional-suite-m20-v1
suite_sha256             = a869623be48e27c4fa39563596c703f1308f0b1a9a9a41c12fdf4a36c28146b1
total_cases              = 64
opportunity_spec_id      = dse-utility-kernel-v0.1
opportunity_spec_sha256  = 8c5dbb384df0bb73e2b8db6dd9b8a97cf31ef904ecca8a5bf4411f5e8e696439
aggregation              = population_any
```

The private manifest is stored with the bundle in operator-controlled private
storage and carries the opportunity ID/hash, aggregation and total case count.
The evaluator recomputes the bundle SHA-256 from the private bytes at load time.

The earlier M16 suite pin
`4791850327e4f4fead67e668c6a4d7e155048653b8cabf5fdede47c31b91f8a4`
is superseded for M20-bound V0.1 measurement. Its original bytes were not
recovered, so it is not silently relabeled as an M20 suite.

## Construction constraints

The frozen suite uses only valid inputs from the public M20 task contract and
covers all eight public task families. Held-out inputs and exact expected JSON
results were generated before any scientific pilot outcome was inspected.

Submission execution is isolated per current-generation submission inside the
evaluator process tree. A non-terminating or exiting submission is bounded and
treated as failed for that submission rather than preventing other population
members from being evaluated. Per-case aggregation remains `population_any`.

The evaluator emits only aggregate pass/fail/total counts. It does not expose
case identity, input, expected output, per-submission output, stdout or stderr.

## Pre-acceptance validation

Before changing the public pin, the private bundle was loaded through
`FilesystemHiddenSuiteStore` and its SHA-256 was recomputed from disk.

A bounded reference submission below the public 4000-byte limit passed every
private case in a logic-level self-test. A deliberately non-terminating
submission was also tested alongside that reference submission: it timed out
without changing the aggregate result. The same non-terminating submission
alone passed no cases.

These checks validate suite semantics and population isolation, but they are
not the final M21 research-runtime acceptance.

## Remaining acceptance gate

M21 is not accepted until the exact frozen private bundle is exercised through:

```text
ExternalEvaluatorClient
  -> TLS EvaluatorService
  -> HardenedEvaluatorWorker
  -> FilesystemHiddenSuiteStore
  -> GVisorDockerBackend
```

The acceptance run must produce runtime-measured gVisor evidence and exact
suite/spec/policy/runtime/build bindings, return aggregate-only sanitized
results, leave world state unchanged and clear the research-runtime readiness
gate.

A public fixture, ordinary Docker/runc execution or a test-double does not
satisfy this gate.

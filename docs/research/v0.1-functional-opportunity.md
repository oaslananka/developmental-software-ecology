# V0.1 Functional Opportunity — DSE Utility Kernel v0.1

M20 freezes the substantive public functional opportunity used by the V0.1
P/T/E/ES/RIL experiment.

The opportunity is public. The evaluator cases are private.

That separation is deliberate:

```text
public task semantics
        |
        v
agent cognition + treatment-specific accessible history
        |
        v
current-generation submission.py
        |
        v
private held-out inputs + expected outputs
        |
        v
aggregate functional score
```

## Canonical identity

The SHA-256 is computed over the exact canonical `public_brief` string in
`src/dse/contracts/experiment.py`.

Changing any public task semantics requires a new spec identity/hash. A result
from one opportunity spec must not be compared as though it came from another.

## Why the task family is public

The research question is whether persistent culture changes the capability a
new generation can reconstruct under equal opportunity.

It is not a test of whether an agent can guess a hidden problem statement.

All five treatment conditions therefore receive the same task-family
semantics. What remains hidden is only the evaluator's held-out case material:
concrete inputs, expected outputs, case composition and diagnostics.

## Submission contract

A current generation may publish one bounded pure-Python module through the
treatment-independent `functional_submit` action.

The module defines `solve(payload)`. The evaluator supplies only valid
payloads described by this document. `payload` has
`{"task": "<task-name>", "args": {...}}` and the return value must be
JSON-compatible.

Submissions must use deterministic Python standard-library computation only.
They must not depend on filesystem or other I/O, network, subprocesses,
environment variables or secrets, wall clocks, or randomness.

## Public task families

### stable_unique

Input `{"items": [scalar, ...]}`, where scalar is null, bool, int or string.
Return first-occurrence uniques. Equality uses the same JSON type and value, so
`true` and `1` are distinct.

### range_pack

Input `{"ranges": [[a,b], ...]}` with integer `a <= b`. Sort by `(a,b)`
and merge overlapping or integer-adjacent ranges whenever
`next_a <= current_b + 1`. Return the merged ranges.

### bucket_total

Input `{"rows": [{"key": k, "value": v}, ...]}`, with lowercase ASCII
identifier keys and integer values. Return
`[{"key": k, "total": sum}, ...]` sorted by key.

### rank_select

Input `{"rows": [{"id": s, "score": n}, ...], "k": k}`, with unique ASCII
IDs, integer scores and `k >= 0`. Return up to `k` IDs ordered by score
descending, then ID ascending.

### dependency_layers

Input `{"nodes":[s,...],"edges":[[u,v],...]}`, where nodes are unique ASCII
strings and edges are directed dependencies `u -> v`. Repeatedly emit the
lexicographically sorted zero-indegree frontier as one layer.

For a DAG return `{"cycle":false,"layers":[[...],...]}`. If any cycle exists
return exactly `{"cycle":true,"layers":[]}`.

### route_min

Input
`{"nodes":[s,...],"edges":[[u,v,w],...],"start":s,"goal":s}`, with directed
positive-integer edge weights. If unreachable return
`{"cost":null,"path":[]}`. Otherwise return minimum total cost and path,
breaking equal-cost ties by lexicographically smallest full node sequence.

### counter_patch

Input `{"base":{key:int,...},"ops":[op,...]}`. Operations are
`{"op":"set","key":k,"value":n}`,
`{"op":"add","key":k,"value":n}`, or
`{"op":"delete","key":k}`. Apply in order. Add treats a missing key as zero;
deleting a missing key is a no-op. Return the final object.

### window_sum

Input `{"values":[int,...],"width":w}` with `w >= 1`. Return the sum of each
contiguous width-`w` window. Return `[]` when `w` exceeds input length.

## Population aggregation

V0.1 uses `population_any`.

For each hidden evaluator case, the evaluator may test every current-generation
submission in the population. A case passes if at least one current-generation
submission returns the exact expected JSON result without exception.

The primary Functional Culture Score remains
`passed_hidden_cases / total_hidden_cases`.

This permits specialization across agents while keeping the functional
opportunity identical across treatments.

## Hidden-suite boundary

A scientifically valid private suite for this opportunity must:

- declare the exact `spec_id`, `spec_sha256` and `population_any`
  aggregation in its private manifest;
- contain only valid inputs from the public domains above;
- hold concrete inputs and expected outputs outside the public repository,
  prompts, agent memory, world events and snapshots;
- contain enough cases across all eight task families to avoid a one-case
  showcase result;
- not disclose case-level diagnostics back to agents or the world;
- return aggregate pass/fail totals only.

The evaluator handshake protocol is v0.2 and binds the suite and opportunity
identity before execution.

## Evidence binding

M20 binds the public opportunity identity through:

```text
manifest
  -> compute fingerprint
  -> evaluator handshake
  -> private suite manifest
  -> culture evaluation snapshot
  -> evaluation plan / plan hash
  -> hardened worker validation
  -> persisted functional report / result hash
```

A mismatch fails closed.

## Turnover and causal interpretation

Functional submissions are current-generation phenotype/output and are deleted
on turnover. Treatment-defined public cultural substrates persist according to
condition.

Any post-turnover advantage must therefore be reconstructed into a new common
submission by the replacement generation before it can improve the hidden
functional score.

## Non-claims

M20 does not reveal or create the canonical private hidden suite, establish
that the currently pinned V0.1 suite hash has recoverable provenance, prove any
model can solve the public task family, prove cumulative culture, or replace
replicated P/T/E/ES/RIL runs and uncertainty reporting.
